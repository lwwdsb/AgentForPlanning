最难的部分是把可观察状态、费用与时间保持一致：生成结果提交后旧报价必须失效；模型等待不能被模拟工具时间抵消；保存事务失败不能留下成功产物；重复请求必须在初始化模型之前命中原记录。这些问题用边界测试和数据库实际内容验证。

实施中有两项具体改进：将实际步骤依赖、费用明细附加到保存方案；把旧候选脚本与当前可复用脚本区分开，同时保留原成功状态和账本。对应回归测试已通过。

工程收获（本轮 AI 实施观察）：先确立金额、时钟、事务和调用上限，再把模型当作可替换决策来源，能用离线测试定位大部分执行器错误；但离线测试无法回答真实模型是否会按工具结果合理重规划。不能把高测试数量当作真实决策质量。

真实模型补充阶段：DeepSeek 四次尝试中取得两条目标路径。第一次预算尝试因为重估字段漂移停止；给模型更精确的下一步约束后完成。第一次故障尝试显式重试原候选，未命中替代形式目标；按规格完善通用提示后完成替代。改动没有放宽预算守卫，也没有让执行器直接替模型选择。四次运行的命令耗时分别约 12.07、13.01、12.58、18.43 秒，其中两次并发，不能把它们相加作为整个开发阶段墙钟用时。补充阶段的可核对计时边界见 [计时记录](../examples/test-results/real-validation-session.json)。

尚需由用户本人完成：亲自复现、解释关键取舍、记录个人修改及学习收获。仓库没有虚构个人手写代码或人工验收；本地实现、116 项测试与两条真实动态路径已完成，最终 Git SHA 由交付消息给出。

范围限制：不实现跨运行失败续跑、同条件脚本改写、跨主机恢复、多用户 Runtime 或线上部署。外部工具恰好执行一次、任意模型/输入的可靠性和供应商账单未验证。当前真实方案仍有内容形式与未确认活动规则问题，详见 [评估](03-evaluation.md)；工具状态完成不能替代正文审核。模型 token 费用不计入合成业务预算。
