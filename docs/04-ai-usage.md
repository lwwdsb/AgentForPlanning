# AI 辅助与贡献记录

用户提供了考核规则、业务题目和验收要求，依次审阅并授权了 Spec Kit 需求、设计、任务和修订工作。本轮用户确认是“选题 2”，提供 GitHub 仓库，先选择完成离线验证，随后提供 DeepSeek 配置继续真实验证。

本轮代码、测试、合成数据、演示脚本和评审文档由 Codex 辅助生成并在本机执行验证。没有采用运行时多 Agent 或 Agent 框架。此前设计阶段的调研记录见 [research.md](../specs/001-content-planning-agent/research.md)。

目前没有观察到用户亲自修改源代码，因此不将 AI 生成内容记作个人手写贡献，也不代用户编造学习经历。用户本人理解、修改和口头解释这些实现的能力尚未由本仓库验证。

| AI 辅助内容 | 验证方式 |
|---|---|
| 金额、时间、请求身份与状态类型 | 精确金额、历史支出、时钟顺序与截止边界测试 |
| 工具、循环与模型协议适配 | 同一执行器的场景测试、假 HTTP 协议测试；DeepSeek 四次实际尝试、两条目标路径 |
| SQLite、幂等和证据导出 | 表约束/事务回滚检查、跨子进程重复执行、只读导出重试 |
| 合成资料与运行证据 | 批量脚本调用公开 CLI，实际生成输入、输出、Trace 与 manifest |
| 评审说明 | 对照需求逐项链接实际证据；AI 阅读核对保存内容与源素材 |

测试顺序：先建立共享基础，再写正常链路测试并观察缺执行器导致失败，随后接通实现；故障/恢复测试先观察 9 项失败再实现并转绿。部分输入、预算和幂等约束已在共享基础中实现，后续故事测试直接通过，没有人为制造失败。最终复核又发现保存方案缺依赖/费用明细、旧脚本误列为当前可复用，两项分别先写失败测试再修正。

全部运行记录来自实际执行，没有用预写日志代替运行。Junit 报告仅移除本机 hostname 元数据；用例、计数、耗时、结果和时间戳保持原始值。干净环境命令报告将本地路径替换为 `<PROJECT>` / `<CLEAN_ENV>`，不影响对命令和结果的核查。

后续个人实践建议：亲自修改一项费用或耗时规则，预测并核对新的结果；解释为什么生成后要重估、为什么换方案不清零费用、为什么保存成功仍可能因额度或时间未完成。真实模型已补充具体模型名、提示修改和实际观察；这些记录可用于本人复现与解释。

本次真实接入由 Codex 对照 DeepSeek 官方文档修改 schema 发送格式和非 thinking 配置，新增三项回归测试后总计 116 项通过。第一次预算运行暴露重估字段漂移，补充精确候选字段反馈；第一次故障运行只重试原候选，按已批准规格补充优先评估替代形式的提示。四次记录全部保留，未修改历史输出以满足验收；具体版本与结果见 [真实验证](../examples/real/README.md)。模型生成正文的未确认事实和形式不匹配另列于 [评估限制](03-evaluation.md)。

密钥只保存在被 Git 忽略、权限为 0600 的本机配置中；公开输入、Trace、报告与提交材料均检查过密钥泄露。真实 API token 消耗独立于合成业务费用，调用记录中的费用数值不是供应商账单。
